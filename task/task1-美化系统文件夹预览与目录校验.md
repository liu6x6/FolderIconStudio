# 任务 1：美化系统文件夹预览与目录校验

## 目标

1. 将当前手绘多边形文件夹预览替换为接近 macOS Finder 的系统通用文件夹外观。
2. 仅允许用户选择可修改的普通文件夹。
3. 明确拒绝 `.app`、`.bundle`、`.framework`、`.plugin`、`.pkg` 等包目录，以及无写入权限的目录。

## 实施步骤

1. 从 CoreTypes 的系统通用文件夹图标读取基础图像，并在不可用时使用 AppKit 的文件夹系统图像。
2. 在基础图像上采用保留高光和阴影的合成方式应用用户颜色，替换原有手绘路径。
3. 将目录验证抽取为可复用的公开服务方法，读取 `isDirectory`、`isPackage` 和 `isApplication` 资源属性，并检查常见包扩展名。
4. 使用文件系统可写性校验，选择、拖放和写入 Finder 图标前均执行同一验证。
5. 在用户尝试选择不合格目录时显示具体错误；为验证逻辑补充测试并运行构建与测试。

## 验收标准

- 预览轮廓、比例和高光阴影来自 macOS 系统通用文件夹图标，不再是自绘多边形。
- `.app` 和其他包目录不能成为目标目录。
- 不可写目录不能成为目标目录，也不能进入 Finder 图标写入流程。
- 合法、可写的普通目录仍能正常选择、预览、应用和恢复图标。

## 完成结果

- 已改为从 `CoreTypes.bundle` 的 `GenericFolderIcon.icns` 读取 macOS 系统文件夹外观，并保留原始高光与阴影后再合成用户颜色。
- 目录选择器已禁止将文件包当作普通目录；拖放和选择完成后都会执行同一验证。
- 已拒绝应用程序、包目录、普通文件、根目录和无写权限目录，并向用户展示具体失败原因。
- 已新增普通目录、`.app`、普通文件和只读目录的验证测试。
- `swift test` 通过 6 项测试；`xcodebuild` 成功构建 GUI App。

## 迭代：改善文件夹视觉质量

1. 检查系统提供的文件夹图标资源及可用替代资源。
2. 调整上色算法，避免纯色覆盖抹掉 Finder 文件夹的材质、阴影与高光。
3. 以系统默认文件夹图标为无图层时的预览基础，并加入更自然的颜色变体。
4. 构建并验证新的渲染输出。

### 迭代结果

- 使用系统标准文件夹、打开文件夹和群组文件夹三种 `CoreTypes` 底图；用户可在右侧“文件夹样式 → 底图”切换。
- 默认使用标准文件夹底图；上色透明度由 72% 降至 28%，并在上色后重绘 34% 原始图像，以保留系统图标的材质、高光与阴影。
- 新增三种底图均可正常渲染的自动化测试。
- `swift test` 通过 7 项测试；Xcode GUI App 构建成功。
