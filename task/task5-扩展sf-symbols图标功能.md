# 任务 5：扩展 SF Symbols 图标功能

## 目标

1. 支持输入任意 macOS 可用的 SF Symbol 名称并添加到画布。
2. 提供分类浏览与名称搜索，快速选择常用 Symbol。
3. 允许编辑 Symbol 的名称、单色颜色与单色/多彩渲染模式。

## 实施步骤

1. 定义分类化的常用 Symbol 目录，包含通用、工作、通信、媒体和自然五类。
2. 在资源栏增加 Symbol 名称输入、添加按钮、分类选择与实时搜索。
3. 使用 `NSImage(systemSymbolName:)` 校验输入名称；无效名称展示明确错误。
4. 为 `SymbolLayer` 增加可持久化的渲染模式；兼容既有模板数据。
5. 在属性面板添加 Symbol 名称、渲染模式和单色颜色编辑项。
6. 调整渲染器：单色模式使用用户颜色，多彩模式使用 SF Symbols 原始多彩外观。
7. 添加模型兼容性与 Symbol 校验测试，并构建 GUI App。

## 验收标准

- 用户可输入任意有效 SF Symbol 名称并添加到画布。
- 分类与搜索可以筛选常用 Symbol。
- 无效 Symbol 名称不会添加图层，并显示提示。
- 单色模式会应用用户颜色；多彩模式显示系统多彩 Symbol。
- 已保存模板在升级后仍可正确加载。

## 完成结果

- 资源栏现在提供 SF Symbol 名称输入和添加按钮；有效名称通过系统 `NSImage` 校验后才会添加。
- 新增通用、工作、通信、媒体和自然五类常用 Symbol，并支持分类切换和实时名称搜索。
- 选中 Symbol 后可编辑名称、选择单色/多彩模式；单色模式可设置颜色，多彩模式使用系统原生配色。
- 已为旧模板缺少渲染模式字段时默认单色提供解码兼容性。
- `swift test` 通过 13 项测试，Xcode GUI App 构建成功。

## 迭代：完整符号目录与独立属性

1. 查找系统可用的 SF Symbols 目录来源；若无公开枚举 API，则将完整目录作为应用资源维护。
2. 将 Symbol 目录、搜索和添加校验从主视图拆分为独立 Swift 文件。
3. 将 Symbol 的名称、渲染模式和颜色移至明确的“Symbol 属性”区域。
4. 确保目录包含完整 SF Symbols 名称，而不再仅显示示例项。

### 迭代结果

- 已将完整 SF Symbols 目录导出为应用资源 `sf-symbols.json`，包含 8,302 个当前系统 Symbol 和 30 个系统分类标签。
- 新增 `SFSymbolCatalog.swift`，集中管理完整清单加载、分类与搜索；新增 `SFSymbolLibraryView.swift`，承载 Symbol 资源栏与属性区 UI。
- 主视图不再包含 Symbol 目录、搜索或属性控件实现。
- 右侧为选中 Symbol 显示独立的“Symbol 属性”区，明确提供“单色模式颜色”选择器；多彩模式会禁用该选择器并说明原因。
- `swift test` 通过 13 项测试；完整目录加载测试验证 8,302 条名称。

## 迭代：Symbol 性能与单色渲染

1. 限制初次渲染的 Symbol 单元数量，并提供分批加载，避免一次创建 8,302 个视图。
2. 预计算分类集合与数量，避免 Picker 每次重绘重复扫描完整清单。
3. 使用 SF Symbols 的单色 palette 配置渲染用户选择的颜色。
4. 添加红蓝 Symbol 输出必须不同的渲染回归测试。

### 迭代结果

- Symbol 目录按系统分类预索引；分类数量不再在 UI 重绘期间扫描完整清单。
- 默认显示“物体与工具”分类，并且每次最多渲染 200 个图标；搜索、切换分类或点击“显示更多 Symbol”可访问完整目录。
- 单色模式改用 SF Symbols palette 配置，用户选择的颜色会直接参与符号渲染。
- 新增红蓝单色 Symbol 输出不同的回归测试。
- `swift test` 通过 14 项测试；Xcode GUI App 构建成功。
